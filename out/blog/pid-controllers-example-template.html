PID Controllers: Building Intuition from Scratch

August 31, 20249 min read

PID controllersProportional-Integral-Derivative controller. A feedback control loop that computes a correction based on current error, accumulated past error, and rate of error change. are everywhere — drones, thermostats, cruise control, robot arms. They're also one of those things that sounds simple until you actually try to tune one. This post builds up the intuition from scratch, starting with the core idea and ending with a working implementation.

Prerequisites

You should be comfortable with basic calculus (derivatives and integrals conceptually) and have seen some Python before. No control theory background needed.

The Core Idea

A PID controller answers one question: given where you are and where you want to be, how hard should you push?

We call the gap between the target and the current state the errorThe difference between the desired setpoint and the actual measured value at a given moment. The controller's entire job is to drive this to zero.:

e(t)=setpoint−measured valuee(t) = \text{setpoint} - \text{measured value}e(t)=setpoint−measured value

The controller's output — how much to actuate — is a weighted sum of three terms:

Each term does something different. Let's break them down.

The Three Terms

P — Proportional

The proportional term pushes proportional to the current error. Big error → big push. Simple.

The problem: pure P control almost always has steady-state errorA persistent, non-zero error that remains after the system has settled. The controller stops correcting once output balances the disturbance, but that requires a nonzero error to sustain.. If you're holding a drone at altitude, the P term stops pushing when error = 0, but gravity is still pulling. You need some nonzero error to keep the drone up — so it settles slightly below target.

I — Integral

The integral term accumulates error over time. If you've been slightly off for a long time, the I term builds up and eventually overcorrects to compensate. This eliminates steady-state error.

The problem: integrator windupWhen the integral term accumulates unbounded because the system is saturated (can't respond further). Once saturation clears, the built-up integral causes a large, sudden overshoot.. If the system is saturated (e.g., motor at max throttle) and still not reaching setpoint, the integral keeps accumulating. When the saturation clears, you get a massive overshoot.

Integrator Windup

Always clamp your integral term to a maximum value in real implementations. Unclamped integrators in safety-critical systems can cause dangerous oscillations or actuator damage.

D — Derivative

The derivative term reacts to how fast the error is changing. It acts like a brake — if error is shrinking rapidly, D damps the response before you overshoot.

The problem: derivative kickA sharp output spike caused by an instantaneous jump in the setpoint. Since the D term reacts to rate-of-change of error, a sudden step change creates a near-infinite derivative.. If the setpoint suddenly jumps, the derivative of error spikes instantaneously, causing a harsh output spike. You can fix this by differentiating the measurement instead of the error (called "derivative on measurement").

A Minimal Python Implementation

Running it on a simple simulated system:

Before / After: Naive vs. Clamped Integral

Before
# No windup protection
self._integral += error * self.dt
return self.ki * self._integral
After
# Clamped integral
self._integral += error * self.dt
self._integral = max(-10.0, min(10.0, self._integral))
return self.ki * self._integral

There are formal methods (Ziegler-NicholsA heuristic method for tuning PID gains by first finding the gain at which the system oscillates (ultimate gain) and the oscillation period, then deriving Kp, Ki, Kd from those values., IMC tuning), but in practice most engineers use heuristics:

The general sequence:

  1. Tune KpK_pKp​ until the system responds quickly but doesn't oscillate badly
  2. Add KiK_iKi​ to push residual error to zero
  3. Add KdK_dKd​ to tame overshoot

Start in Simulation

Always tune in simulation first. A poorly tuned KpK_pKp​ on a real drone means a crash. On a sim, it means you restart the script.

When PID Isn't Enough

PID assumes the system is roughly linearA system whose output is directly proportional to its input. Doubling the input doubles the output. Most real systems are only approximately linear within a limited operating range. around the operating point. For nonlinear systems — like a pendulum swung to full inversion — PID will struggle.

Common extensions:

  • Gain scheduling — different PID gains at different operating points
  • Feedforward — add a model-based term to handle known disturbances (gravity, friction)
  • Model Predictive Control (MPC) — optimize over a future horizon instead of reacting to current error

PID is the workhorse of industrial control. It handles ~95% of real-world applications. But understanding why it works — and where it breaks — is what separates someone who can tune a loop from someone who understands control.
